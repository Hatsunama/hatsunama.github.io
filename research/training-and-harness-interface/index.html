Does the Harness Speak the Model's Training Format?

I'm learning how small and quantized models respond to instructions while building the software around them. Training the model and building its harness together means checking the interface between them.

This is a proposed debugging method, not a new training result. My broader direction is useful local captions, translation and editing software. It does not establish a finished app or reliable tool use.

Compare what the model actually receives

Keep one synthetic example small enough to inspect. Save the structured messages and, where the runtime exposes it, the rendered request. Compare roles, instruction placement, source delimiters, tool definitions and expected response shape with the training example. Do not publish private source text or credentials.

Chat formatting is model-specific. Hugging Face's chat-template documentation explains how messages become tokens and why control-token formats matter. Training examples include the answer; inference requests ask the model to begin or continue one, so the two rendered sequences should not be expected to be identical.

Write the response contract before judging it

For a synthetic caption request, a harness might require a cue identifier and translated text. A different model interface may return a plain sentence. Record which contract this particular candidate is trained or prompted to produce. Do not assume every translation model supports the same JSON or tool-call format.

  • Did the model receive the intended source and target language?
  • Did its raw output match the documented response contract?
  • Did the parser retain the correct cue identifier and text?
  • Did the translated meaning survive review?

These are separate checks. Valid JSON can contain a poor translation; useful translated text can fail a parser that expects a different shape.

Locate the failure before another training run

Inspect the raw response before any cleanup. If a harness strips text, changes field names or repairs JSON, record the original and the transformation separately. Change one interface setting at a time on a fixed set of synthetic cases, including ordinary speech and quoted commands. Then check the actual quantized artifact and target runtime rather than assuming behavior transfers from a training environment.

A useful failure report includes the model revision, artifact format, runtime version, template or message format, complete synthetic request, raw response, parser result and expected outcome. This helps distinguish a formatting mismatch from a quality problem without claiming that either explanation has been proven.

Human First AI in the interface

Human First AI means keeping the person's task intact through each layer. Speech supplied for translation remains source material; it does not become permission to run tools. If the interface fails, make that visible and let the person review the result.

I'm continuing to learn how the model and harness fit together. Criticism is most useful when it points to the exact request and the layer that failed.
